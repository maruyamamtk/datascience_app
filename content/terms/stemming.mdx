# ステミング

「learning」「learned」「learns」はすべて同じ動詞「learn」の活用形だが、文字列としては別物なので、そのまま頻度を数えると1つの概念が3つに分散してしまう。**ステミング** は、語尾のパターンを見て接尾辞を切り落とし、これらを同じ «語幹» にまとめる処理。

## 単純なルールベースの例

1. 語尾が「-ies」なら「-y」に置き換える（studies → study）。
2. 語尾が「-ing」（十分長い語のみ）なら取り除く（learning → learn）。
3. 語尾が「-ed」なら取り除く（helped → help）。
4. 語尾が「-s」（「-ss」は除く）なら取り除く（models → model）。

これらのルールを語ごとに順番に試すだけで、多くの英単語をそれらしい語幹にまとめられる。

## «実在しない語幹» になることがある

ステミングは辞書を引かず、あくまで文字列のパターンだけで機械的に切り詰める。そのため "programming" に上記ルールを適用すると "programm" のような **辞書に載っていない語幹** になることがある。これはバグではなく、ステミングという手法の本質的な特徴——**見出し語化（lemmatization）** との違いがここにある。

| | ステミング | 見出し語化 |
|---|---|---|
| 方法 | 接尾辞パターンの機械的な切り詰め | 辞書・文法情報を使った基本形への変換 |
| 結果 | 実在しない語幹になることがある（例: programm） | 常に実在する基本形（lemma）を返す |
| 速度 | 高速 | 相対的に低速（辞書引きが必要） |

どちらも目的は同じ——「表記が違うだけの同じ概念」を1つにまとめることで、[tf-idf](tf-idf)や[共起ネットワーク](co-occurrence-network)の語彙数を減らし、統計をより意味のある単位に集約する。実務では速度重視ならステミング、精度重視なら見出し語化が選ばれる。

[ストップワード](stop-words)除去のあとにステミングを適用するのが典型的な順序——先に機能語を取り除いてから、残った内容語だけを語幹に正規化する。
